# Client Push Notifications Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clients get iPhone push notifications about what their coach does (plus a daily workout reminder), with a switch per type, quiet hours, an unread badge and a Today permission card.

**Architecture:** Database triggers write `push_outbox` rows (security definer, coach/member actor only, client recipient only). pg_cron calls a new `send-push` Edge Function (shared secret, like `award-workout`) every minute to send due rows and every 15 minutes to enqueue daily reminders. The function applies preferences, quiet hours and grouping with pure functions from `packages/shared`, and sends straight to APNs over HTTP/2 with an ES256 token (WebCrypto). The phone registers its APNs device token, edits preferences, routes taps and keeps the badge.

**Tech Stack:** Postgres (Supabase migrations, pgTAP, pg_cron, pg_net, Vault), Deno Edge Functions, TypeScript `packages/shared` (vitest, zod), Expo SDK 58 + expo-router + expo-notifications 58.1.8, Maestro.

**Spec:** `docs/superpowers/specs/2026-11-09-client-push-notifications-design.md` (approved mockups: canvas `https://claude.ai/artifact/QfcJamEADw95Y4HwEqCxXM`, boards Main, Settings, Notifications, LockScreen; their copy is quoted in the tasks below).

## Global Constraints

- Every node/pnpm command runs as `eval "$(fnm env)" && fnm use 24 && <command>`, inside the worktree `/Users/parvjain/Desktop/fitness-tracker/.worktrees/push-notifications`.
- Clients only. Coach notifications, Android, rich notifications, per-conversation mute are out of scope.
- Type keys (exactly these 11): `workout_assigned`, `workout_changed`, `daily_reminder`, `coach_logged`, `still_training`, `message`, `workout_comment`, `meal_comment`, `food_targets`, `community_coach_post`, `community_activity`. All default **on**.
- Defaults: reminder time `08:00`; quiet hours on, `22:00`–`07:00`; anything inside quiet hours waits until the end of the window, in the client's time zone.
- Lock screen text says **who and what, never the content**: no message, comment or meal text, no body data or weights. Coach name = coach's first name; community grouping uses the first reactor's first name.
- Database changes only in `supabase/migrations/`; every new table has RLS; every policy has a pgTAP test proving cross-client and cross-workspace access fails. Regenerate `packages/shared/src/database.types.ts` with `pnpm db:types` after each migration (CI diffs it).
- Shared logic lives in `packages/shared/src/push/` as pure functions with vitest tests (the shared suite also runs under `TZ=Pacific/Auckland`). `packages/shared/src/index.ts` re-exports with `export * from './push/index';` — explicit file path, never a directory import (`scripts/sync-functions-shared.sh` appends `.ts`).
- Edge Function: `send-push`, `verify_jwt = false`, header `x-push-secret`, env `SEND_PUSH_SECRET`; Vault secrets `send_push_url`, `send_push_secret`. APNs secrets: `APNS_KEY_P8`, `APNS_KEY_ID`, `APNS_TEAM_ID=88L5M6CC34`, `APNS_TOPIC=app.caltracker.client`, `APNS_ENV=sandbox|production` (TestFlight = production). Tests never call Apple: APNs `fetch` is injected and mocked.
- Retries: up to **5** attempts, then give up. Invalid tokens (410, `BadDeviceToken`) delete the device row.
- Hosting stays portable: no Cloudflare/Vercel APIs; background work in Supabase only.
- Mobile builds are local `xcodebuild` (no EAS); `ios/` is generated by prebuild and not committed.
- TDD: failing test first, then code. Before calling a task done: `pnpm check` (typecheck, lint, test) plus the task's db/functions tests, output shown.

## Review Focus

- **Debug build against a production sender:** a locally built Debug app carries `aps-environment = development`, so its token is a sandbox token; with staging `APNS_ENV=production`, Apple answers `BadDeviceToken` and the row is deleted silently. Expect the PO to test with TestFlight builds, and the function to log which environment rejected the token so it is diagnosable. (Test: Task 8 `logs the APNs environment when a token is rejected`.)
- **One iPhone, two accounts:** after Sign out and sign-in as another client (or Sign out failing offline), the old account's pushes must never reach the phone. Expect `register_push_device` to move the token to the new user. (Test: Task 1 `register moves a token from another user`; Task 9 `unregister runs before signOut and never blocks it`.)
- **Bulk coach actions:** assigning a 12-week program or a Live Sync of a library workout touches dozens of workouts; the client expects one "New workout assigned" and at most one "Today's workout changed" — no flood, nothing for other days. (Test: Task 5 `assign_program enqueues exactly one row` and `live sync enqueues only today's copy, once`.)
- **Time zone unknown or stale:** a new client's `profiles.time_zone` is `'UTC'` until the phone syncs it; quiet hours computed in UTC would ping a US client at 3 AM. Expect the coach's zone as fallback (`public.client_zone`), UTC only when nothing is known. (Test: Task 6 `context falls back to the coach's zone`.)
- **Taken-back reactions:** someone reacts and un-reacts within the 5-minute gathering window; the client expects no "Sam reacted to your post." (Test: Task 5 `un-reacting removes the pending push`.)
- **Merge note (not a test):** branch `feature/units-in-settings` (unmerged) rewrites the same Settings sheet in `apps/mobile/src/components/today/today-header.tsx` (adds a kg/lb picker, moves Close to the title row, Sign out to the bottom after a flex spacer). Task 11 inserts the Notifications row immediately **above the "Coached by" line**, which exists in both versions, so whichever merges second resolves a small textual conflict only. Migration timestamps `20261109000100`–`20261109000300` must still sort after every migration on `origin/main` when this merges.

## Rulings on spec gaps (PO to confirm in plan review)

1. **Meal comments do not exist** (food spec: "there are no meal comments"; coaches use "Reply about this meal", which is a message). `meal_comment` stays in the catalogue and the DB check, has no trigger, and its switch is hidden (`available: false`) until meal comments are built.
2. **Time zone:** no `notification_prefs.time_zone` column. `profiles.time_zone` is already kept equal to the phone's (`apps/mobile/src/lib/awards.ts` `syncTimeZone`, on start and on foreground), and `public.client_zone()` adds the coach fallback. One zone, not two.
3. **Badge** = unread coach messages (after `conversation_reads.last_read_at`) + unread `community_notifications` of kind `comment`. Workout comments have no read state in the app, so they are not counted.
4. **Daily reminder** is enqueued by `send-push` (job `reminders`, every 15 minutes) so `reminderDue` stays the single rule in shared. Due window: the 60 minutes after the reminder time, same local day. Several workouts today: title `Today: Upper A + 1 more`.
5. **Text is built at send time** by shared builders from the row's `data`; `title`/`body` are written to the row when sent (audit).
6. **Gathering windows:** `community_activity` waits 5 minutes and later rows join the same send time; `workout_changed` (2 min) and `food_targets` (1 min) collapse to one pending row; everything else sends on the next minute. Message bursts group to "Luis sent you 3 messages."
7. **Day-bound types** (`workout_changed`, `daily_reminder`) are dropped (outcome `expired`) when quiet hours would push them to a later local day.
8. **`still_training`** stays on-device, is not delayed by quiet hours, and follows the switch (cached on the phone so it works offline).
9. **Community activity** = comments and reactions on the client's own **post** (not on their comments); reactions and comments group separately per post. Copy: "Sam reacted to your post.", "Sam and 1 other reacted…", "Sam and 4 others reacted…" (same for "commented on your post.").
10. **Coach-logged** pushes only when the coach finished the log (not auto-finished by the hourly job).
11. Notification permission is requested with badge allowed, from the Today card and from the existing first-workout ask. "Later" hides the card for 7 days.
12. Time rows open an in-app list of times in 30-minute steps (no new native dependency).
13. Assigned text follows the spec: "Luis assigned you Strength Block." (the lock-screen board's "(8 weeks)" is not used).
14. Entitlement: delete `apps/mobile/plugins/without-push-entitlement.js` (it exists only for the free team). expo-notifications then writes `aps-environment = development`; an App Store/TestFlight export re-signs it to `production`. Requires the paid team for signing.

**Interfaces:**
- Consumes: `public.workspace_members`, `public.profiles` (`first_name`, `full_name`), test helpers `tests.create_user/create_workspace/add_client/act_as`.
- Produces:
  - `public.push_devices(token text pk check (token ~ '^[0-9a-f]{64,200}$'), user_id uuid not null → auth.users on delete cascade, platform text not null default 'ios' check (platform = 'ios'), app_version text check (char_length ≤ 32), created_at, updated_at)`. Index on `user_id`. RLS: select own rows only; no direct insert/update/delete for `authenticated`.
  - `public.register_push_device(p_token text, p_app_version text) returns void` — security definer, `42501` when `auth.uid()` is null; upserts by token setting `user_id = auth.uid()` (moves a token from any other user), stamps `updated_at`.
  - `public.unregister_push_device(p_token text) returns void` — deletes only the caller's row with that token.
  - `public.notification_prefs(user_id uuid pk default auth.uid() → auth.users on delete cascade, disabled text[] not null default '{}' check (disabled <@ array[<the 11 keys>]), reminder_time time not null default '08:00', quiet_enabled boolean not null default true, quiet_start time not null default '22:00', quiet_end time not null default '07:00', updated_at timestamptz not null default now())`. RLS: select/insert/update own row (`user_id = (select auth.uid())`). Grants: `insert (disabled, reminder_time, quiet_enabled, quiet_start, quiet_end)`, `update` of the same columns. No row = all defaults.
  - `public.push_outbox(id uuid pk, user_id uuid not null → auth.users on delete cascade, workspace_id uuid → workspaces on delete cascade, type text not null check (type in the 11 keys minus 'still_training'), group_key text not null, title text, body text, data jsonb not null default '{}', not_before timestamptz not null default now(), created_at timestamptz not null default now(), sent_at timestamptz, attempts integer not null default 0, last_error text, claimed_until timestamptz, outcome text check (outcome in ('sent','disabled','no_device','expired','failed')))`. Indexes: `(not_before) where sent_at is null`; `(user_id, group_key) where sent_at is null`; **unique** `(user_id, group_key) where type = 'daily_reminder'`. RLS enabled, no policies; `revoke all` from `anon, authenticated`; `grant all` to `service_role`.
  - `private.push_enqueue(p_user uuid, p_workspace uuid, p_type text, p_group_key text, p_data jsonb, p_delay interval default '0', p_dedupe boolean default false) returns void` — no-op unless `p_user` is a `client` member of `p_workspace`. With `p_dedupe` and a pending row (`sent_at is null`) for the same user+group_key: replace its `data` and return. Otherwise insert with `not_before = coalesce(<earliest pending not_before for that user+group_key>, now() + p_delay)` so late joiners share the send time.
  - `private.push_is_coach(p_workspace uuid, p_user uuid) returns boolean` (owner or staff) and `private.push_first_name(p_user uuid) returns text` (`first_name`, else first word of `full_name`, else `''`).
