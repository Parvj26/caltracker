# Messages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each coach–client pair gets one private conversation, with text, up to 4 photos and YouTube cards. It shows unread counts and "Seen", and updates live while the app is open. It works on both the dashboard and the phone. The phone keeps an offline outbox.

**Architecture:**
- Postgres tables with RLS. One definer function creates or gets the conversation.
- `client_msg_id` makes sends idempotent.
- Supabase Realtime `postgres_changes` delivers new messages live.
- A private `message-images` bucket stores photos.
- Pure helpers live in `packages/shared`: unread and seen state, day grouping, YouTube detection, and the outbox merge.
- Push notifications are not part of this plan. They are added later with the paid Apple account.

**Tech Stack:** Postgres/pgTAP, Supabase Realtime and Storage, Next.js 16, Expo SDK 58, Vitest, Playwright, Maestro.

**Spec:** `docs/superpowers/specs/2026-11-05-messages-design.md`

**Branch:** `feature/messages` from `main`, using the next free migration numbers at build time. It depends on coach profile (avatars) for headers. Build it after profile merges, or fall back to initials until then.

## Global Constraints
- One conversation per (workspace, client).
- Message body is 0–4000 characters. Each message has at most 4 images, and needs a body or at least one image.
- `unique (sender_id, client_msg_id)`. A retry of the same send gives the same row.
- No editing or deleting messages, no typing indicators, no voice notes, no groups.
- Images are compressed on the device or in the browser: at most 1600 px plus a thumbnail, as WebP. Paths are `{workspace_id}/{conversation_id}/{uuid}.webp` and `-thumb.webp`. Only the two participants can read or write them.
- The web inbox sorts by `last_message_at`. Clients with no messages come after, sorted by name. Past clients are excluded.
- **Copy:**
  - "Messages"
  - "Unread"
  - "Seen"
  - "📷 Photo"
  - "Sending…"
  - "Didn't send · Retry"
  - "Today" / "Yesterday" / "Mon 2 Nov"
  - "Watch on YouTube"
- Realtime is the primary update path. The web also refetches on focus. The phone refetches on foreground.
- Tokens only. Bubbles are at least 44 px tall where tappable.

## Review Focus
1. **The same message sent twice by the outbox** (an app kill mid-send). The `client_msg_id` makes the second send a no-op, and the phone shows one bubble. Test: Tasks 1 and 4.
2. **Another client in the same workspace trying to read the conversation.** It must be refused. Test: Task 1 (pgTAP).
3. **Realtime dropping** (a laptop sleeps). Focus or foreground refetch catches up, and the unread counts end up correct. Test: Task 3 (Playwright: an insert while the tab is hidden, then focus, then it appears).
4. **A long message, or a burst of emoji.** It wraps without overflowing. Test: Tasks 3 and 4 (screenshots).
5. **A removed client's history.** It is readable by the coach on the past client's page, and no new message can be sent to it. Test: Tasks 1 and 3.

### Task 1: Data, policies, storage
**Files:** `supabase/migrations/<next>_messages.sql`, `supabase/tests/messages.test.sql`, the generated types.

**Produces:**
- **`conversations`:** `id`, `workspace_id`, `client_id`, `created_at`, `last_message_at`. Unique on `(workspace_id, client_id)`.
- **`messages`:** `id`, `conversation_id`, `workspace_id`, `sender_id` (default `auth.uid()`, no column privilege), `body`, `image_paths text[]`, `client_msg_id uuid`, `created_at`. It has the checks listed above. A trigger copies the workspace from the conversation and bumps `last_message_at`.
- **`conversation_reads`:** `(conversation_id, user_id)` is the primary key, plus `last_read_at`.
- **`get_or_create_conversation(p_client_id uuid) returns uuid`:** definer function. The caller must be the coach of that client, or the client themselves. It returns the existing row if there is one.
- **`mark_conversation_read(p_conversation_id uuid)`:** definer function. It upserts the caller's read to `now()`.
- **RLS:** select is allowed for the workspace coach and the conversation's client. Insert into `messages` is allowed only as yourself, into a conversation you belong to, and only while the client is a current member.
- **Storage:** the `message-images` bucket and its policies.
- **Realtime:** the publication includes `messages` and `conversation_reads`.

- [ ] **Step 1: Write failing pgTAP.**
  - Coach and client can read; another client, another coach and anon cannot.
  - Insert as someone else is refused.
  - A duplicate `client_msg_id` is refused, and the insert is a no-op when made through `on conflict do nothing`.
  - Empty body with no images is rejected, and so are 5 images.
  - `get_or_create` called twice returns the same id. Called by another coach's client, it gives 42501.
  - Insert after the client was removed is refused. History stays readable to the coach.
  - Storage: participants can read and write; non-participants are denied.
